## 2. 授权边界与验收方法

本轮按以下边界执行：

- **未安装、未卸载**测试包；未验证真实覆盖升级与卸载后用户数据保留。
- **未启用、安装、配置或移除 Windows OpenSSH Server**。
- 打包应用的运行验收使用独立 `--user-data-dir` 临时目录；没有读写本机现有 `%APPDATA%\TermForge`。
- SSH/SFTP 服务端为本地 `ssh2` 夹具服务器（RSA 2048 主机密钥、密码认证、简化 Shell 与内存/磁盘夹具），**不是 Windows OpenSSH Server**，PTY 行为为简化实现。
- 未为测试向生产代码添加开关；验收脚本位于 `tests/acceptance/`。
- 打包应用通过 Chrome DevTools Protocol 驱动真实生产渲染层与 `window.termforge` bridge；没有逐一点击所有 UI 控件。

### 5.4 验收期间发现并修复的产品问题

首次运行验收时，主机密钥变化检查失败：

```text
expected host-key-changed, got {"code":"internal","message":"SSH 连接过程中发生内部错误，请重试。"}
```

失败报告：[`release/acceptance/2026-10-22T12-32-13-948Z/runtime-report.json`](../../release/acceptance/2026-10-22T12-32-13-948Z/runtime-report.json)。

根因：`evaluateHostKey` 在记录具体失败之前调用 `verify(false)`；ssh2 会从 verifier 回调中同步发出通用的 `Host denied (verification failed)` 错误，`handleError` 先把状态写成 `internal`，随后 `fail('host-key-changed')` 因状态已是 `error` 而不再覆盖。安全行为本身仍是拒绝连接，但错误分类不准确。

修复：

- `SshService` 新增 `failHostKey`，先写入具体失败，再释放 ssh2 verifier（[SshService.ts:771](../../src/main/services/ssh/SshService.ts#L771)）；变化分支使用该路径（[SshService.ts:671](../../src/main/services/ssh/SshService.ts#L671)）。
- `mapSshClientError` 将 `host denied` 归为 `host-key-verification-failed`（[sshFailure.ts:137](../../src/main/services/ssh/sshFailure.ts#L137)）。
- 单元测试模拟 ssh2 同步错误（[sshService.test.ts:328](../../tests/unit/sshService.test.ts#L328)），并补充错误映射断言（[sshFailure.test.ts:59](../../tests/unit/sshFailure.test.ts#L59)）。

修复后重新执行 typecheck、lint、284 项测试、生产构建、打包与完整运行时验收；最终 15/15 通过。本文件所有产物哈希均对应修复后的构建。
